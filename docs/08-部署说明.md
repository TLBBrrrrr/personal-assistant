# 部署说明：HTTP API 服务

> 更新：2026-11-28 · 状态：**已部署并可公网访问**
> 服务器：`137.74.174.80`（Ubuntu 24.04 / Python 3.12）· 端口 `8000`

## 1. 这是什么

在原有 CLI 之外新增了一层 FastAPI HTTP 服务，把对话能力暴露成 REST 接口，供网页/App 多终端调用。核心逻辑仍复用同一套 Agent + 6 个工具 + post-turn hooks，没有另起炉灶。

**当前只开放对话能力**（含工具调用）。事件回忆、Garmin 数据查询虽在工具里可用（模型会按需调用），但没有单独的 REST 端点。

## 2. 端点

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/health` | 否 | 探活，返回状态/provider/会话数 |
| POST | `/chat` | 是（`X-API-Key`） | 对话，支持多轮与工具调用 |
| GET | `/docs` | 否 | Swagger 交互文档 |

`POST /chat` 请求体：

```json
{
  "message": "现在几点了？",
  "session_id": "user-123",
  "reset": false
}
```

- `session_id`：会话标识，不同值互相隔离（多终端各用一个）；不传默认 `default`。
- `reset: true`：清空该会话历史，重新开始。

响应：

```json
{
  "reply": "现在是上午 9 点 21 分...",
  "session_id": "user-123",
  "turn_count": 1,
  "hook_notes": ["[hook] 记录一轮对话..."]
}
```

调用示例：

```bash
curl -X POST http://137.74.174.80:8000/chat \
  -H "Content-Type: application/json" \
  -H "X-API-Key: <你的 API Token>" \
  -d '{"message":"你好","session_id":"user-123"}'
```

## 3. 鉴权与安全

- **API Token**：请求头 `X-API-Key`，服务端用 `secrets.compare_digest` 恒定时间比对。未配置 token 时 `/chat` 直接返回 503，避免误部署成公网裸奔。
- Token 存放在服务器 `~/personal-assistant/.env` 的 `ASSISTANT_API_KEY_TOKEN`，文件权限 `600`。**不要提交、不要写进前端代码**——前端应通过自己的后端中转，或让用户登录后由后端下发。
- CORS 当前为 `*`（`ASSISTANT_CORS_ORIGINS`）。生产环境有明确域名后应收紧为白名单。
- **没有 HTTPS**：当前是纯 HTTP 明文，Token 与对话内容在网络上可见。若前端在公网使用，强烈建议在 8000 前挂 Nginx + Let's Encrypt，或走 Cloudflare 等反代终止 TLS。443 端口已被其他服务占用，不能直接复用。

## 4. 会话与数据

- 会话状态在**内存**：`session_id → Conversation`，每个会话一把锁防并发竞争，TTL 默认 24h 惰性清理。**服务重启后所有会话历史丢失**（事件/指标数据不受影响，它们在 SQLite）。
- 事件库 `data/events.db`、指标库 `data/metrics.db` 在服务器 `~/personal-assistant/data/`，随服务持久化。
- **服务器时区是 UTC**：`get_current_time` 返回 UTC 时间（如 09:21 UTC = 北京时间 17:21）。前端展示需按用户时区转换，或修改代码里的时区处理。

## 5. 运维命令

在服务器上（需 sudo 的用 `sudo`）：

```bash
# 服务状态 / 启动 / 停止 / 重启
systemctl status personal-assistant
systemctl restart personal-assistant
systemctl stop personal-assistant

# 看日志
journalctl -u personal-assistant -f

# 更新代码
cd ~/personal-assistant
git pull
# 若依赖有变：.venv/bin/pip install -e .
sudo systemctl restart personal-assistant
```

服务已 `enable`（开机自启）+ `Restart=always`（崩溃 5s 后自动重启）。

## 6. 目录与文件

```
~/personal-assistant/
├── .env              # 模型 key + API Token（600，禁止提交）
├── .env_garmin       # Garmin Personal API key（600，禁止提交）
├── data/             # events.db / metrics.db（持久化）
├── src/assistant/
│   ├── api.py        # FastAPI 服务（本次新增）
│   └── ...
└── .venv/            # Python 3.12 虚拟环境
```

systemd 单元：`/etc/systemd/system/personal-assistant.service`。

## 7. 部署时踩过的坑

- 服务器无 `pip3`、无 `venv`：先 `apt install python3.12-venv`。
- 项目原 `requires-python >=3.13`，服务器是 3.12：已放宽到 `>=3.12`，pip 拉到兼容版依赖。
- 本地验证时 HTTP 代理把 `127.0.0.1` 请求也代理了（502）：测试需设 `NO_PROXY=127.0.0.1,localhost` 或用 `trust_env=False`。
